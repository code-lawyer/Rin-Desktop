# 产品目标、需求与范围

## 要解决的问题

Rin Desktop 面向在 Windows 上使用编程 Agent 的个人开发者：让桌面动态壁纸成为可随时呼出的工作入口，通过对话气泡、项目工作台、电脑麦克风和 RC003 蓝牙遥控器，对明确的项目与会话发出任务、检查草稿、处理审批并听取回复。

产品以已有 Windows 原生 CLI 执行 Agent 任务，本地语音负责输入输出。动态壁纸、会话操作和输入设备服务于同一个项目/会话目标。现阶段开发优先级是可靠性、目标正确、数据连续性，再扩展遥控与多后端。

## 产品范围

0.5.0 在原有基线上整合数据保护、分类设置、遥控草稿闭环和实验 Agent。已稳定继承的范围为：Windows x64、单屏动态壁纸、两个人物、单条回复气泡、可展开阅读、项目与会话工作台、Codex CLI、电脑麦克风听写、本地回复朗读、按需模型准备及通用快捷键。安装版的实际验证边界见[发布记录](../release-audit.md)。

Claude/Grok/OpenCode 与 RC003 随 0.5.0 以实验能力分发，不能因已发布就标为完整验收。RC003 原生音频已连接主应用草稿；用户反馈基本效果可用，完整设备矩阵仍未完成。Hiyori 悬浮模式和 Dots 属于本机可选路径，不成为公共安装版的必需依赖。

后置功能包括有限语音控制语法、精细人物绑定、多屏/跨平台/更多硬件，以及多个后台任务并发。原计划的 WPF、SQLite、原 TUI 共存和三活动任务不能直接当作当前实现；逐项差异见[历史归并表](legacy-reconciliation.md)。

当前交付版本为0.6.1，审查、安装包与同步证据见[发布记录](release-0.6.1-review.md)。2026-10-27用户将动态目标收敛为工作、看向用户两种状态：从同一条15秒720p母片裁出工作循环、转向用户、用户循环、返回工作四段，免费本地超分至3840×2160并[接入主应用](two-state-app-integration-2026-10-27.md)。它是独立播放器，不依赖Wallpaper Engine；两种停留状态持续播放，界面请求在安全片段边界改变人物朝向。不能把超分结果称为原生4K，也不能把工程验证当成美术最终验收。

此前[工作、捧杯、托腮、看雨、陪伴五张静态完整画面](still-set-v2-implementation.md)及男性人物保留，可回切；五张静态图为1586×992生成后超分至3840×2400，既有家具漂移仍属于素材质量限制。小雨、轻敲键盘、语音优先的环境音控制继续保留。精细Live2D、望窗动态和更多姿态不属于当前两态交付；历史“只做静态/停止视频”已被后续用户决策取代。完整目标差距见[本轮全面审查](project-audit-2026-10-28.md)。

## 核心用户流程

1. **首次准备**：安装应用与所选 Windows CLI，按 CLI 官方流程登录；先能文字对话，再按需下载语音模型。缺 CLI、登录、模型或硬件分别显示原因。
2. **文字工作**：选择项目 → 新建或恢复会话 → 明确当前 provider、目录与模型 → 输入并发送 → 查看流式回复或处理审批 → 继续、停止或切换会话。
3. **电脑麦克风听写**：开始捕获时绑定目标 → 明确录音状态 → 停止并本地识别 → 回填该目标的草稿 → 检查/编辑 → 用户确认发送。识别不是执行授权。
4. **目标遥控流程**：方向/确认选择项目与会话 → 按住语音键、松开结束 → 查看草稿 → 单独确认发送 → 明确中断/审批/朗读动作。此流程代码已接入，真实核心流程验收仍待进行；不能用离线测试替代。
5. **回复朗读**：用户选择引擎、声线和驻留策略；可以手动朗读，或明确开启完整回复自动朗读；随时停止。停止播放与卸载模型是不同操作。
6. **失联与恢复**：保留草稿及可核查的会话标识；未知提交不自动重发；恢复失败不静默新建会话代替。DATA-01/02 已有离线回归；未决发送记录保护相关项目入口不被移除，实际断电与账户验收仍单列。

## 必须保留的行为

- 对话投递依赖项目/会话标识，不能靠当前前台窗口粘贴或向任意 Shell 注入。
- 语音不自动提交；普通确认键不自动批准权限。原生 CLI 已配置的权限仍需向用户说明。
- 设备断线、旧连接按键、旧识别结果不重放到新目标；取消不删除已有草稿或历史。
- 本地语音不隐式回退云识别；Agent 文本推理仍按所选服务联网。
- 既有数据目录、CLI 账户、项目文件与个人素材有明确边界；升级和整理不自动合并或清空。
- Codex 沿用已有 CLI 账户；Claude 实验入口要求用户自行配置 API/云平台认证，不能使用订阅额度。所有后端均不自动改变计费来源；各家正式支持仍受 DEC-01 与真实验收约束。

## 验收指标

下表是继承并保留的工程目标，尚非现有产品的全部实测成绩。更改目标需要在决策记录写明理由与范围。

| 指标 | 目标与样本 | 当前证据 |
| --- | --- | --- |
| 按键反馈 | P95 ≤150 ms，冷唤醒单列 | 尚无生产设备路径统计 |
| 真实音频有效 | 正常条件至少 98/100 次 | 仅一次成功诊断记录，不可推出可靠率 |
| 松手到草稿 | 预热后 5–15 秒语音 P95 ≤2 秒，至少 100 段 | 诊断单样本识别约 2.984 秒；不是 P95，仍需优化/评估 |
| 中文技术语义 | 50 条固定语料，至少 90% 无关键语义错误 | 尚未形成完整评分集 |
| 目标与重复操作 | 200 次操作无误投递或非预期重复发送 | 尚未完成遥控主流程测试 |
| 会话恢复 | 每个启用后端 20 个任务，结果可解释 | 新后端尚未完成矩阵 |

语料需包含否定、数字、路径、中英文混合、长停顿和重录。初次配对、登录、选择目录和复杂文本编辑允许鼠标键盘；“全遥控”针对日常核心流程。实际兼容声明只覆盖记录过的机器、CLI 版本、设备固件与显示设置。
