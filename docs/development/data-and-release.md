# 数据、仓库同步与发布

## 持久数据

| 内容 | 位置/拥有者 | 维护约定 |
| --- | --- | --- |
| 源码应用设置、草稿和 profile | 默认 `work/runtime/avatar`；可用 `--storage` 指定 | 整理源码不搬迁；测试使用独立目录 |
| 安装版数据 | `%LOCALAPPDATA%/VibeVoice` 或用户已选择的已有目录 | 保留兼容名称；升级/卸载不清空 |
| 项目入口和设置 | 应用 `workspaces.json` 等 JSON | 通过存储模块序列化写入和替换；数据结构变更需要旧版本样本回归 |
| 新 Agent 的应用侧索引/消息缓存 | 数据目录 `agents/<provider>` | 与 provider 绑定；有正文缓存，不能描述为只存无正文元数据 |
| CLI 账户与原生历史 | 原生 CLI 的用户目录 | 由 CLI 管理，不复制进仓库或渲染页 |
| 模型与运行环境 | 用户数据 `voice-resources`，以及本机保留的旧模型/评估环境 | 按固定清单准备；不要当作源码随意移动或上传 |
| 本机诊断、研究与验收 | `work`、本地 `docs/evidence`/`docs/research` | 私人原始资料；公共报告只提供脱敏结论 |
| 美术母图和可编辑工程 | `artwork` | 保留原始工程；获准运行资产按发布清单提供 |

录音生产流程不默认写磁盘；应用的草稿与新后端消息缓存则确实持久化。不要用早期“草稿只放内存”的设计解释当前行为。完整对外说明见[隐私文档](../privacy.md)。

非空草稿属于未发送输入，不按数量静默淘汰。新Agent历史缓存保留已知轮次结果；外部或旧历史缺少可信完成信息时可展示，但不会被当作成功回复开放朗读。

DATA-01/02 增加每个 provider 最近一次发送记录、提交前原稿保护、原生历史核查及事务写入。`workspaces.json` 和会话 JSON 保存上一份 `.bak`；写入失败可能留下 `.tmp`。损坏文件不自动覆盖，恢复工具先预览，只复制到全新目录，见[交付与恢复说明](data-agent-validation.md)。不明回执原稿和备份均可能包含正文，属于私人数据。

变更数据结构前，应保存独立样本、写清读取兼容和失败回退，并验证写入中断、旧目录导入、项目路径变化及不同 provider。同名 JSON 文件或同名会话并不表示可以合并。测试、备份和日志不得覆盖日用数据。

## 源码同步步骤

1. 运行文档/台账检查、测试、构建和公共工作区扫描。
2. 用 `git status` 和逐文件 diff 区分原有功能开发、本轮整理以及私人资料；不要用整体添加掩盖文件边界。
3. 只暂存本次拟提交的公共源码和文档；运行 `node tools/release/audit-public.mjs --staged` 审查实际 index，并检查暂存差异。
4. 在原仓库开发分支形成可审查提交。需要新分支时用 `codex/` 前缀，保留当前未提交内容，不重置工作区。
5. 推送该开发分支到原 origin 并建立它的 upstream，再按项目流程合入 main。不要把 `origin/main` 当成开发分支的同名 upstream。
6. 记录实际 commit、远端分支与检查结果，更新 REL-02。只有推送成功才说源码已同步。

2026-10-22 开始按用户授权执行 0.5.0 发布：整合后的公共源码、文档和验证工具一并审计、提交；GitHub 同步结果与版本验证记录以[发布审查](../release-audit.md)为准。旧 Test 包、私人资料、模型和运行数据继续保留在忽略目录。

## 应用发布步骤

发布范围先由已通过的任务决定。未验收的设备或后端不能只因为源码已存在就进入正式支持列表。

当前Claude/Grok/OpenCode在界面和portable.json的experimentalBackends中标为实验，标记来自同一catalog。保留源码功能不代表允许跳过REL-01/03；正式支持前仍需逐家真实账户与安装验收。

`npm run package:test -- --id=<新标识>` 生成隔离测试安装器与 ZIP，沿用根目录与应用一致的当前基础版本，不修改正式资源清单或旧产物。测试程序默认使用 `%LOCALAPPDATA%/VibeVoice/test-builds/<标识>`；测试安装器与正式版使用不同 AppId 和目录。包内附源码指纹、离线检查、数据恢复及[验收清单](test-acceptance.md)。这是 REL-01 的候选准备，不能替代人工安装/回滚记录。

按照[构建说明](../build.md)准备固定资源与 Inno Setup；更新应用及根版本、资源清单与必要说明；生成新的独立版本目录，不能覆盖已有 release 产物。执行[测试规范](testing.md)中的安装、升级、卸载、回滚和数据保护场景，记录安装器与文件 SHA-256。

原生 CLI、账号、模型、个人配置、工作数据和制作工具不加入基础安装器。运行资源按许可与锁定清单准备；语音模型从其上游按需下载。第三方对应源码与应用安装附件保持独立，规则见[许可说明](../licenses.md)和[发布记录](../release-audit.md)。

发布完成后同步版本、已验证范围、安装说明与已知限制。源码同步、安装包构建、GitHub Release 上传是三个独立结果。

## 回滚和恢复

文件整理阶段只迁移有清单的开发文件，不改变应用存储格式；后续审查修复增加历史结果恢复并取消草稿数量淘汰，仍读取既有数据。原始文件备份和逐文件移动记录保存在本机整理报告目录，代码修复也有独立基线快照；恢复时只按具体映射和差异处理，不整体重置仓库或覆盖后续修改。

应用版本回滚先核对新旧数据格式兼容，保留当前数据备份，再用旧安装包的独立测试目录验证。回滚不等于删除新数据或 CLI 历史。模型目录和 Qwen 评估环境仍有引用，清理前必须重新检查代码、打包和运行路径。
