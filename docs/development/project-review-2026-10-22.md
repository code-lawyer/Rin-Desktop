### TOOL-04：QA 帮助请求产生执行副作用（P2）

- 位置：[still-desktop.mjs](../../tools/qa/still-desktop.mjs) 第 4–8 行；同根因在 [interface-check.mjs](../../tools/qa/interface-check.mjs) 和 [remote-focus.mjs](../../tools/qa/remote-focus.mjs)。
- 规范：[测试规范](testing.md)约定“默认帮助不会启动真实CLI/GUI”；质量工具指南还要求帮助不创建 fixture。
- 触发：例如 `npm run qa:stills -- --help`。入口没有先解析帮助参数，仍创建报告目录并启动 Electron；缺少 Electron 时会报启动错误而不是显示帮助。
- 证据：将三个真实入口源码置入隔离 VM，仅替换文件创建和进程启动依赖，以 `--help` 运行。三者均请求创建目录及启动 Electron，无帮助输出；没有实际启动 GUI。
- 修复验收：在任何目录、依赖加载或进程副作用前处理帮助参数；将三个入口加入默认帮助契约回归，保留正常 QA 运行能力。

公开边界、打包资源、IPC 来源及进程退出检查未形成其他证据充分的规范缺陷。一般代码气味没有单独列为阻塞项；Codex 子进程退出候选经隔离父子进程实测未复现，已排除。

### FIX-13：草稿保存失败后切换会话丢失新增输入（P1）

- 位置：[draft-session.mjs](../../prototypes/live2d-codex/renderer/draft-session.mjs) 第 47–48 行。
- 需求：[产品流程](product.md)要求“保留草稿及可核查的会话标识”，[数据约定](data-and-release.md)明确非空草稿是未发送输入。
- 触发：会话 A 已有保存的草稿，编辑追加内容后，写盘失败（如磁盘满、文件锁定）；切换到 B，再返回 A。
- 实际：`restore()` 未等待 `save()`，立即换目标、清空输入。失败返回时版本已改变，新增内容没有保留在目标独立的内存副本。真实 `createDraftSession` 复现返回 A 后只剩原来磁盘上的旧稿，新增输入已丢失；错误提示不能恢复它。
- 修复验收：阻止保存失败后的目标切换，或保留可重试且按目标隔离的未保存草稿。覆盖保存失败、保存未结束时切换及返回旧目标，不影响已有草稿与会话身份。

### FIX-14：人物已显示但设置保存失败，画面与声线失配（P2）

- 位置：[main.cjs](../../prototypes/live2d-codex/main.cjs) 第 133–136 行。
- 需求：用户要求声线默认随人物切换；ART-09 要求保留统一声线提交与失败时的一致状态。
- 触发：女生切男生，男生图片已绘制并发送就绪回执，随后 `WorkspaceStore.updateSettings()` 写盘失败。
- 实际：真实设置事务注入 `ENOSPC`，运行真实 `confirmWallpaper()` 后，画面请求仍为男生，设置仍为女生、Qwen Serena、Kokoro 3。处理只改变错误提示，没有回退已显示人物；在重试成功前组合不一致。
- 修复验收：协调画面切换与设置提交；失败后保持可见人物、保存人物及默认声线一致，并验证重试、连续切换与失败晚到。

### FIX-15：旧朗读超时清除新朗读的环境音降音状态（P2）

- 位置：[main.cjs](../../prototypes/live2d-codex/main.cjs) 第 572–573 行。
- 需求：ART-09 要求异步加载、取消和异常“不串状态”；[方案](static-wallpaper-plan.md)要求旧计时器不能覆盖新状态。
- 触发：第一轮朗读等待静音回执，用户停止后开始第二轮，第一轮的等待先超时，第二轮随后收到成功回执。
- 实际：真实 `speech:playback` handler 的旧 `catch` 无归属检查地设置 `speaking=false`；新一轮仍获准播放。雨声恢复普通音量，手动工作姿态下键盘声也可恢复，违反朗读降音优先级。
- 修复验收：所有异步完成与失败清理核对当前播放请求归属；覆盖旧失败晚到、新成功，以及采音和暂停并发。

### FIX-16：壁纸渲染进程崩溃后听写与朗读持续超时（P2）

- 位置：[main.cjs](../../prototypes/live2d-codex/main.cjs) 第 51 行。
- 需求：[方案](static-wallpaper-plan.md)要求图片或音频故障各自降级，不阻止朗读或听写。
- 触发：壁纸 renderer 退出，但 BrowserWindow 仍存在；随后启动电脑听写、RC003 听写或朗读。
- 实际：音频门禁只判断窗口是否存在，仍等待已退出 renderer 的回执。用真实 `AmbientBarrier` 与主进程 handler 模拟 `render-process-gone` 后，电脑听写与朗读均持续超时；设置中环境音已关闭仍失败，提示关闭环境音无法恢复。RC003 复用同一门禁，未进行硬件试验。
- 修复验收：确认播放器已停止时允许安全降级，或提供有效的渲染器恢复；不能简单忽略仍可能发声的无响应播放器。验证环境音关闭、已退出、无响应、恢复和重新开启分支。
