# DATA-01 / DATA-02 / Agent 离线契约交付

范围：当前源码的数据保护、无真实账户的协议契约，以及供人工验收的独立测试包。本页保留基于 0.4.0 的 Test 候选证据；当前 0.5.0 的分发与验证见[发布审查](../release-audit.md)。带 `Test` 的产物始终是隔离测试候选。

## DATA-01：发送确认与草稿

主进程通过 `submission-guard.mjs` 管理发送。请求进入原生 Agent 前，先把原稿、provider、项目、原始/当前会话、发送标识和核查基线写入 `workspaces.json.submissions`。保存失败就不发送。每个 provider 最多有一个尚未确定的发送，跨项目切换也不能绕过它；其他 provider 的数据相互隔离。

状态为 `pending → confirmed / unknown / not-sent`。重启时未完成的 `pending` 转成 `unknown`。用户明确核查后可以将未知记录标为 `released`，保留草稿并解除发送保护；这个操作本身不发送任何文字。

Codex 的轮次回执/开始通知、Claude/ACP 的实际回复、工具请求或结果可证明请求到达。NativeAgent 本地队列返回不算原生 Agent 已接收。确认之前输入仍保留，界面显示发送状态及原稿；确认后只移除仍与本次原稿完全相同的草稿，后续编辑不清空。

核查只读取原生历史，不使用应用乐观插入的消息缓存充当回执。优先匹配 Claude 客户端消息标识，否则要求发送前完整用户消息前缀未变、只新增一条匹配消息。没有找到、读取失败、历史截断或多条可疑消息都继续保留未知状态。ACP 无稳定消息标识，因此保守地保留不能证明的结果；没有“自动重试一次”的路径，也不承诺跨进程绝对 exactly-once。

首次创建会话时，新 ID 在提交任务前写入发送记录。气泡草稿迁移先写新位置，再清理旧位置；失败保留旧草稿。未确认原稿还保存在发送记录中，重新打开后可查看。每个 provider 保留最近一次记录；下一次有意发送替换该记录，已发历史继续由原生 CLI 保存。

## DATA-02：兼容、写入与恢复

- 继续读取 format 1、旧 Codex 草稿键、`lastThreadId`、已有声音/按钮设置和 provider 独立索引；不移动日用数据、模型或 CLI 账户目录。
- 存储修改进入同一个队列，在副本上计算，文件同步并替换成功才发布到内存。打开文件、flush、rename 失败均不污染已提交内存状态，后续重试可恢复。
- 保存前保留上一份已提交 JSON 为 `.bak`；`.tmp` 是未提交恢复候选。主文件有效时始终优先使用主文件。损坏或主文件缺失但存在恢复副本时停止读取，不把它当成空安装，不静默覆盖损坏原件。
- 使用真实路径统一目录联接和 Windows 大小写；别名下有不同旧草稿时保留并合并展示所有不同正文。项目目录丢失时仍保留项目和草稿，不猜测它的新位置。
- “使用已有数据目录”先验证工作台及各 provider 记录，再原子更新目录指针。失败保留当前选择。指针指向不可访问目录时启动明确报错，不悄悄改用空白默认目录。
- 原生 Agent 索引先于会话指针提交；两个文件不是跨文件数据库事务，原生 CLI 才是完整历史的来源。旧索引缺少轮次结果时仍标为 unknown。

恢复工具入口：`npm run data:recover -- --source="<已关闭应用的数据目录>" --out="<不存在的新目录>"`。默认只检查并预览；增加 `--run` 才复制。默认使用 `workspaces.json.bak`，`--from=pending` 明确选择 `.tmp`。工具只向全新、位于源目录之外的目录写入，保留源目录和副本中的旧主记录。恢复后在应用中选择这份副本；它不恢复原生 CLI 的账户或丢失的历史。

这套回归模拟写入/flush/替换失败，不是断电设备实验。`.bak` 只有上一份提交，不替代用户的独立备份；恢复到旧备份可能缺少最近修改。应用启动与安装的实际表现仍需验收。

## 无账户协议矩阵

| 能力 | Codex | Claude | Grok | OpenCode |
| --- | --- | --- | --- | --- |
| 创建、恢复、模型、历史 | 合成 app-server + 实际状态逻辑 | SDK 边界替身 + 实际适配器 | 已安装 ACP SDK + 合成 stdio 对端 | 已安装 ACP SDK + 合成 stdio 对端 |
| 发送与流式最终正文 | 回执前完成/丢失确认/流式 | partial + 完整消息去重 | 文本分块、子会话过滤 | 文本分块、子会话过滤 |
| 审批允许/拒绝/过期 | 命令/文件/权限仅本轮 | 原始工具参数与单次决定 | 只选择 allow_once/reject_once | 只选择 allow_once/reject_once |
| 问题与表单 | 保留问题 ID、拒绝缺项 | AskUserQuestion、多选/中止 | 原生问题扩展 + ACP 表单 | ACP 表单 |
| 工具期间停止与退出 | 轮次定向中断、连接关闭 | 取消问题、结果停止、EOF | cancel、进程退出、协议关闭 | cancel、进程退出、协议关闭 |
| 晚到事件与所有权 | 旧/其他轮次、关闭后消息 | 旧连接工具回调、关闭/结束后的结果 | 其他 session、旧连接、结束后分块 | 其他 session、旧连接、结束后分块 |

权限差异保持明确：Codex 本轮授权；Claude 不继承 bypass 与项目 hooks；Grok 独占进程、关闭 yolo/auto，拒绝 bypass hook；OpenCode 继续遵循其原生项目/全局/Agent 权限，原生配置自动允许的操作不保证弹窗。空闲或旧连接发来的权限请求被拒绝。

测试不启动真实 Agent CLI，不登录、不花费额度、不采集音频、不连接 RC003。它证明当前适配器与锁定 SDK 的离线协议行为，不能证明厂商 CLI 版本、账户权限或实机操作成功。
