# 2026-10-23 女生状态与可见差异核查

用户反馈：只观察到两张身体动作一致、面部细节/画风不同的静态图，没有看到其他动作。本轮只核查并汇报，没有改图片、自动规则或正在运行的应用设置。

结论：当前有六个可选状态和六张完整资源，但显示内容都是同一身体底图加头部变化，不等于六种明显不同的完整动作。工作/阅读的动作区分不足，生成头部与原图的细节和风格差异比动作差异更显眼；这与用户的观察相符。

## 实际六种状态

| 状态 | 实际画面变化 | 自动触发与停留 |
| --- | --- | --- |
| 专注工作 | 原始坐姿，双手在笔记本上 | 正常闲置的主要画面，每次 75–120 秒；任务执行时保持工作 |
| 阅读屏幕 | 头部/眼神小变化；没有单独的手部停敲动作 | 正常闲置随机选中，24–40 秒 |
| 望向窗外 | 头部与视线轻微朝画面左侧 | 正常闲置随机选中，20–35 秒 |
| 闭目休息 | 闭眼，身体、手仍沿用原图 | 正常闲置随机选中，8–14 秒 |
| 看向你 | 头部面向用户 | 打开对话框、采音、朗读、等待审批或错误状态；更高优先级规则以源码为准 |
| 轻轻微笑 | 回应姿态上轻微闭嘴微笑 | 成功回复事件后 3 秒；采音、朗读等更高优先级状态可覆盖 |

[状态规则](../../prototypes/live2d-codex/renderer/still-policy.mjs)不是六张依次轮播：每个闲置变化后回到工作，再随机选下一种，且避开上次非工作状态。首次选择权重是阅读 3、望窗 2、休息 1；没有保证在固定时间内展示全部状态。

[渲染器](../../prototypes/live2d-codex/renderer/still-wallpaper.js)的 `compose()` 始终先画 work 母版，再替换女生头部区域，身体、手、笔记本和背景不换。工作与看向你是原有 3840×2400 图片；另四张源图是 1586×992，放大头部也带来细节柔化，但面容/画风漂移不能只归因于分辨率。

## 为什么容易只看到少数状态

- 闲置计时仅在自动、未暂停、页面可见、对话框关闭、没有采音/朗读/任务/审批/错误时推进。打开气泡或任务忙碌会暂停计时，不会继续按墙钟轮播。
- 正常工作图先停留 75–120 秒；阅读本身又很接近工作，闭眼则只有 8–14 秒。
- 另一个应用的前台窗口覆盖显示器工作区时，桌面宿主会暂停壁纸；锁屏、休眠和手动暂停也阻止切换。代码不是“任何小窗口遮住一点桌面就暂停”。
- 本次启动日志曾多次进入 `connection:ready/status:error`，按规则会保持看向你并暂停闲置计时；随后已记录 `configuring → idle`。不能把较早的错误当作当前仍未恢复。

当前保存的选择是女生、原画、`stillPose:auto`。六张女生文件的尺寸和 SHA-256 均与清单一致，运行日志没有发现姿态加载失败，且存在多次渲染就绪事件。现有日志只保存渲染尺寸，不保存 `pose`，所以不能据此断言用户刚才看到的恰好是哪两张，也不能把渲染事件数量当作不同姿态数量。
