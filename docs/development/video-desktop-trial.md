# 视频壁纸与完整桌面应用整合

> 路线变更（2026-10-22）：用户已明确放弃视频片段方案，当前方向为 [4K 静态壁纸与环境音](static-wallpaper-plan.md)。下文是此前研究/试用的历史记录，后续视频制作与验收计划已停止；已有代码和素材保留，主应用视频入口已由 ART-09 退出，当前实现见[原画恢复与第一阶段小样](static-wallpaper-preview.md)。

ART-06 将 [独立视频样例](video-companion-preview.md) 的播放器接入现有主应用。它沿用原来的 Windows 桌面承载、对话气泡、工作台、Agent、语音与遥控器服务，只新增一种壁纸渲染方式。运行不需要 Steam、Wallpaper Engine 或参考壁纸的脚本。

## 体验方式

先准备原项目依赖、视觉资源以及 ART-05 的本地素材副本，然后运行：

```powershell
npm run start:video-desktop
```

此入口打开当前源码及对话框，数据仍使用源码的默认目录。要保留已经配置好的语音、项目和遥控器设置，先关闭原应用，再生成独立试用目录：

```powershell
npm run trial:video-desktop -- --run --id=local-video-trial --data-source="<已关闭应用的数据目录>"
```

命令构建完整应用，复制三个视频及海报，并将现有数据和语音资源复制到 `work/runtime/video-desktop-trials/<id>/data`。浏览器缓存、组件缓存和旧的数据位置指针不复制，拒绝目录联接及覆盖已有试用目录。已有 Qwen 资源路径保留。双击生成的 `Start-Video-Desktop.cmd` 启动；原数据不被试用版修改。只运行一份应用，避免多个实例竞争全局快捷键、语音和遥控器。该目录含本机素材与私人数据，仅供本地体验，不是公共发行包。

托盘的“壁纸与视频播放”打开相应设置页。用户可以选择原女生、原男生或视频样例；视频提供跟随任务的自动状态，也可手动选择陪伴、专注、等待回应，暂停、重新入场和失败重试。默认视频静音，朗读仍由原语音服务输出，音量仍由原播放控件及遥控器控制。

## 行为与兼容边界

- 自动模式在任务执行时选择专注，等待确认或连接异常时选择等待回应；空闲时根据对话框是否打开选择等待回应或陪伴。样例片段只验证状态连接，动作与服装尚未统一成自己的角色素材。
- 新视频或原画实际就绪后才替换当前画面，并通过原来的 `confirmWallpaper` 入口保存人物与默认声线。失败时保留当前画面和声线，工作台显示明确的重试按钮。
- 壁纸采用等比覆盖，不做脸部、身体网格变形。更换窗口尺寸只改变裁切和对话框的头部锚点。
- 对话提交、草稿、朗读/停止/音量、电脑听写、RC003 连接与输入映射、快捷键、模型准备和工作台六类设置继续使用原实现。视频播放器不处理音频输入，也不替代这些服务。
- 媒体通过应用自己的 `app://local/video/` 协议读取，支持 Range、HEAD 和文件白名单；包内只加入视频、海报和清单。静态原画与素材缺失时的选择入口仍保留。

共享媒体约束和服务位于 [video-catalog.mjs](../../prototypes/live2d-codex/backend/video-catalog.mjs)、[video-media.mjs](../../prototypes/live2d-codex/backend/video-media.mjs)。两种渲染方式的就绪交接见 [wallpaper-renderer.js](../../prototypes/live2d-codex/renderer/wallpaper-renderer.js)，视频绑定见 [video-wallpaper.js](../../prototypes/live2d-codex/renderer/video-wallpaper.js)。

- 试用应用已实际启动，1080p 视频解码就绪，并通过原 Windows 桌面承载成功附着。Codex 连接成功但保存的上次会话恢复失败；当前遥控设备未发现，界面保留新对话及重新连接入口。实际语音加载、会话发送与物理遥控操作仍需用户验收，未把进程存活当成功能通过。
