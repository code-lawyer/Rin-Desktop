# 女生 Live2D 半身样例

ART-02 已提供独立交互预览，但 **2026-10-22 用户明确否决其人体比例、脸型与变形效果，美术验收未通过，退回返工**。当前文件是失败样例和技术验证材料，不能称为合格的新角色。它没有接入当前桌面的人物选项、用户设置或发布资源清单；现有男女壁纸继续使用原模型。

## 2026-10-22 画面问题复查

复查对照了原女生壁纸、生成的正面母图、拆件图、拼装图、导出模型及浏览器中的正面/单轴小幅/端点姿态。此轮没有重新生成角色或宣称已修复美术。对整体人体美感没有可靠的自动判定器，采用实图对照；可数值复现的素材拉伸则单独设诊断门槛。

### 已确认的原因

1. **拆件没有保留母图的共同坐标和尺寸。** 部件图是第二次独立生成的图集，不是母图的对齐分层。`assemble.mjs` 又使用 `resize(..., { fit: 'fill' })` 分别拉伸部件。实际 PNG 尺寸与表中的目标尺寸一致，排除了仅是脚本未执行的可能。

   | 部件 | 横向缩放 | 纵向缩放 | 宽高比相对原部件 |
   | --- | --- | --- | --- |
   | 左马尾 | 0.960 | 1.963 | 0.489 |
   | 右马尾 | 1.120 | 1.959 | 0.572 |
   | 刘海/前发 | 1.355 | 1.006 | 1.347 |

   这些变形在中立姿态就存在。脸和身体各自的缩放基本等比，但它们仍是独立重绘后重新摆放的部件；“各自等比”不证明它们组合后的头身、五官和颈肩比例正确。不能把全身比例问题全部归因于马尾缩放。
2. **颈部、五官和发层结构不足以支撑自然转头。** 本机 MCP 返回的实际模型层级中，脖颈合在 Body 里，没有独立颈部；鼻子与耳朵合在 Face 里，瞳孔/眼白/睫毛也没有分别拆开。前一轮为遮住颈部接缝，把 Body 从 y=486 上移到 y=455，而没有重做颈部跟随。这覆盖了间隙，同时改变了静态颈肩关系。图集中标作后发的部件还带有前部刘海，和前发重叠。程序能够移动这些大块，但缺少正确的遮挡与体积变化。
3. **减小运动范围只能减轻动态问题。** 固定其他参数，用同一份 MOC3 对比 AngleX=0、±10、±45，并在浏览器关闭风后检查小幅和端点动作。±10 时脸部网格包围盒宽高比相对中立改变不足 1%；±45 单轴约改变 2–3.2%，组合角最多约 6.4%。这是含透明边缘的网格包围盒，并非解剖测量，也不证明局部五官正确。缩小参数范围不能恢复已经改变的母图比例。参数数值不等于实测转头度数。
4. **没有证据表明画布把人物横纵分别拉伸。** 播放端使用同一个 `model.scale.set(scale)` 等比缩放。优先返工素材和绑定，而不是替换 Cubism/Pixi 播放器。当前未证明存在父子变形器重复应用的引擎缺陷，不能把观察到的层级直接判为算法 bug。

复现入口为 [halfbody 诊断](../../tools/qa/live2d-halfbody-diagnose.mjs)：

```powershell
npm run qa:halfbody:diagnose
npm run qa:halfbody:diagnose -- --run
```

默认仅帮助；显式运行读取本地样例的字面量摆放表、PNG 尺寸和实际 MOC3，并保存新报告到 `work/qa/live2d-halfbody-diagnosis`。本样例的素材宽高比保留检查为红色，退出码 1，明确报出上述三个发层。5% 只是发现非等比缩放的诊断阈值，不是美术标准；此脚本不自动判定人物是否好看或是否通过验收。原画文件、两个正式壁纸及失败模型均保留。

复查维护验证：`npm run check:project`、`npm run check:public`（工作区审计）和 `npm run test:halfbody`（4 项）通过，诊断帮助与语法检查通过；诊断实跑两次均检出相同三个发层，失败证据未抹除。本轮只增加诊断、澄清报告范围并更新台账，没有改动前端或模型，没有重新声称全量应用测试通过。

### 工具核实与能力边界

- **现有 PSD2Live 能精修，不限于一次自动绑定。** 此次实际连接已安装的 3.4.5 本机 MCP，读取了工作区、41 项对象/部件层级及 `rig_deform` schema；它支持指定关键形的平移、缩放、旋转、弯曲、局部选区与 landmark 对齐。前一轮的闭眼/唇线修改也保存在可编辑工程中。因此这些操作可由 Agent 执行，不必全部由人用鼠标完成。但接口成功、导出成功均不是美术质量承诺。参见[固定版本制作接口](https://github.com/tsunehimatoi/psd2live/blob/v3.4.5/docs/zh/agent/MCP_AUTHORING.md)。
- **内置图像生成可以辅助补画，但本轮图集已经证明它不能当作精确拆件器。** 不能依靠“同一人物”的提示词就假定多次生成会保持像素对应、轮廓和五官比例。后续应在共同画布上保留可见原像素，并针对遮挡区域补画；必须复合检查。
- **See-through 更适合验证同图分层。** 官方提供 23 类部件输出、PSD，以及面向 8 GB 显存的 NF4/卸载路径。本机显存量级支持考虑该路线，但本仓库尚未部署其权重、依赖或执行这张人物的推理；不能从官方内存数字推断本机已可运行。作者也明确说明拆件输出不包含完整绑定，仍需美术调整。[作者说明与低显存入口](https://github.com/shitagaki-lab/see-through)。
- **Qwen-Image-Layered 是备选，不是现成成品生成器。** 它输出多层 RGBA/PSD，官方说明提示词不能精确指定每层语义。适合尝试补充分层，不宜直接承诺眼睑、瞳孔、口腔能按要求拆好。[官方项目](https://github.com/QwenLM/Qwen-Image-Layered)。
- **插件查询没有找到专用 Live2D/Cubism/PSD2Live 插件。** 宽泛查询返回的图片、视频工具也没有证明可交付可编辑 Cubism 绑定；生成角色视频不解决这个模型的制作问题。插件目录查询不代表外界不存在其他工具。

专业效果需要针对角色的美术修正；这不等于技术上强制要求每一步由人手操作。当前已证明的能力是制作和驱动真实 MOC3、修改部分关键形及完成声音联动，**尚未证明能独立稳定产出符合本项目画风与比例要求的精细角色**。官方 Cubism 的面部自动生成同样要求先准备分离部件和变形器，并提供运动修正步骤，不能视为任意图片的一键成品方案。[官方流程](https://docs.live2d.com/en/cubism-editor-manual/face-auto-edit/)。

### 下一版应如何验收

2026-10-22 根据用户继续要求更好计划，收窄为以下制作方案。此处是待实施计划；没有因此产生新素材、部署拆件模型或证明修复完成。

**冻结原画身份，先证明头颈小样，再扩展半身。** 以已有女生壁纸的 attention 原画为母版，先沿用其中的脸型、光影和姿态，取头颈区域进行小样制作。当前拼装失败模型只留作失败证据。第一阶段不重新生成整个人物，也不为了套自动绑定模板强改成对称正面；斜向原画不能直接套用只支持正脸的官方面部自动生成，须按原姿态定制关键形。

| 阶段 | 具体制作与交付 | 放行依据 |
| --- | --- | --- |
| 1. 原画分层保真 | 对同一母图试用 See-through 拆件，所有层保留统一画布坐标；保留可见原像素，补画限于眼下、发下、口腔及颈部等运动需要暴露的区域。交付原图/复合图切换对照和改动区域说明。 | 静态脸型、五官位置、颈肩比例、发根和光影不发生可见漂移；部件不靠非等比拉伸凑位置。未通过就不开始运动绑定。 |
| 2. 头颈关键形 | 用 PSD2Live 的逐关键形接口修正中立、左右、上下及四个组合角；独立处理眼白、瞳孔、眼睑、鼻耳、唇线/口腔和颈部。先固定身体与风，分别检查转头、半眨眼、闭眼、半张嘴。交付同尺度姿态对照和可单独调节的模型。 | 产生可辨认的连续转头，脸廓、五官透视与颈部连接协调；没有眼球压扁、五官滑动、双唇重影或露底。幅度由实际画质决定，参数数值不充当物理角度。 |
| 3. 头部动态试片 | 提供约 10–15 秒连续试片和交互预览，依次展示转头、眨眼、实际语音口型，再展示组合动作；保留母图在旁对照。 | 中间帧和慢速往返同样自然，能够认出原壁纸人物；由实图和用户反馈确认，不以加载成功、零翻折或图层数放行。 |
| 4. 半身与头发 | 头部路线得到效果证据后再扩展肩颈/半身、发根固定和发尾物理，沿用已实现的音频驱动。若补全原画被遮住的身体，只在缺失区域补画并单独检查。 | 头身比例维持母版，肩颈和发层动作协调；再次检查连续转头、眨眼、语音口型与头发组合。仍先提供独立预览，原壁纸继续可用。 |

**自动制作的止损条件：** 先完成一轮同图拆件实验；对明确可定位的问题最多做两轮定向修正，每轮保存原图对照和失败点。若静态身份/比例仍不通过，或头部运动始终需要明显牺牲脸型才能成立，就停止扩展自动方案，交付可编辑分层、问题清单和关键形参考，建议由专业美术/Live2D 建模者接手拆件与绑定。我继续承担运行时、语音同步、交互和验证。此计划不代表已经委托外部人员或确认其费用。

See-through 是这个实验的候选拆件器，不是成品质量保证；其作者明确将精细美术分层和绑定列为后续工作。专业美术参与是更稳妥的成品路线，自动实验的作用是验证可以承担多少工作，而非承诺替代全部美术制作。不以“改小幅度”“图层更多”或“零翻折”替代上述验收。

## 打开样例

在仓库根目录运行 `npm run preview:halfbody`，然后打开 `http://127.0.0.1:5317`。服务只监听本机。页面提供自动演示、鼠标跟随、手动转头/俯仰、眨眼、轻风和语音播放，也支持选择本地音频。模型失败显示重试；声音停止或播放结束会立即关闭嘴部。

预览源码在 `prototypes/live2d-halfbody`，启动工具为 [preview-halfbody.mjs](../../tools/project/preview-halfbody.mjs)。主应用的 Pixi、Cubism Core 和显示库继续原地使用。`npm run build:halfbody` 只构建预览，不启动服务。构建产物写入被忽略的 `work/runtime/halfbody-preview`。

预览还需要本机已制作的 `artwork/female-halfbody-v1`：`runtime/Generated_artwork.model3.json`、MOC3、贴图及其引用文件，以及 `sample.wav`。这些美术源文件和音频遵循仓库既有本地素材规则，不会因增加源码入口自动进入公开仓库；干净克隆需要另行准备这套样例素材。

## 已实现的范围

| 能力 | 实现与边界 |
| --- | --- |
| 连续转头 | 真正的 Cubism 网格插值；使用 Angle X ±45、Angle Y ±20 的模型参数范围，UI 显示归一化百分比。这些数值不是人物物理转角测量，只用于小角度半身表现，不支持侧脸/背面。 |
| 眨眼 | 独立左右眼与闭眼层；定时眨眼和手动触发。修正自动闭眼网格翻折后，眼睛收拢并淡出，闭眼层接管。 |
| 口型同步 | Web Audio 对实际播放的 PCM 做能量分析，驱动 MouthOpenY；包括加载中停止、播放结束和解码失败恢复。当前是开合幅度同步，没有音素级 a/e/i/o/u 嘴形。 |
| 头发摆动 | 前发、双马尾独立网格。预览用阻尼弹簧响应转头速度和轻风，驱动 HairFront/HairBack；导出包也保留物理文件，但此页的最终发丝参数由预览控制器写入。 |
| 声音 | 使用已有本地 Kokoro 中文女声 3 生成约 13.37 秒的固定样例；不调用账户，不采集麦克风。自选音频仅在浏览器本地解码。 |

模型有 14 个输入部件、16 个导出网格（含两条已隐藏的重复自动唇线）和 20 个参数。17 个参数在离线采样中实际改变网格或透明度；眼球 X/Y/Form 尚未独立制作，因此不宣称瞳孔独立跟随。
