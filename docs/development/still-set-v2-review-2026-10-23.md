## Spec

### FIX-17 / P2：姿态恢复后工作台继续显示旧姿态和错误

需求要求工作台显示“当前画面及暂停/交互原因”。[主进程](../../prototypes/live2d-codex/main.cjs)的 `companion:render-ready` 仅在 `wallpaperStatus.phase === 'ready'` 时更新姿态与活动。

复现步骤：

1. 女生工作图已显示，设置自定义两种声线。
2. 令尚未缓存的捧杯图加载失败，保持原工作图和原声线。
3. 恢复资源访问并改选有效的看雨图。
4. 壁纸实际成功显示看雨，但工作台仍显示“当前画面：伏案工作 · 固定姿态”，同时显示加载失败和重试按钮。
5. 额外点击人物重试后，状态才恢复为看雨；自定义声线保留。

原因是同人物姿态切换复用已提交的请求，成功绘制时不再次进行人物提交；失败已将状态置为 `error`，后续有效的姿态回报又被上述条件挡住。此后自动轮换、暂停及交互原因也不能正常更新到工作台，直到额外重试。

这是状态同步缺陷，已通过隔离 Electron、生产页面和预加载接口复现；实际画面与声线未在该复现中丢失。应允许当前已提交人物的有效恢复回报清除对应姿态错误，同时保持对旧请求、未提交人物和迟到回报的拒绝。该问题尚未修复。

维护复现入口：`npm run qa:stills -- --pose-recovery`。报告先记录失败保图、自定义声线保持、有效姿态恢复后的实际/界面状态及显式重试结果，然后断言正常恢复应达到 `ready`；当前以退出码1正确暴露缺陷。此模式不改变正常 `qa:stills` 的检查范围。
