# 技术决策与待决事项

本页区分已采用实现、原设计差异和未解决的产品选择。当前用户目标是“动态壁纸＋Agent＋蓝牙遥控器”，要求保留既有功能、数据和原 GitHub 关系。

## 已采用的路线

| 决策 | 依据 | 后果 |
| --- | --- | --- |
| 保留现有 Electron 主应用 | 当前源码与 0.4.0 已发布实现 | 继续在主应用上集成；不重建 WPF 主界面 |
| 保留主应用现有目录名 | 构建、模型、资源清单、历史工具与本机环境存在引用 | 目录职责明确即可；改名不作为本轮完成条件 |
| CLI 通过结构化接口调用 | Codex RPC、Claude SDK、ACP 源码已存在 | 不采用任意前台粘贴；每家能力以契约与真实验收为准 |
| JSON 索引和持久草稿 | 现行 WorkspaceStore 与 NativeAgent 实现 | 旧 SQLite/仅内存草稿方案归档；隐私说明需反映正文缓存 |
| 本地 SenseVoice/Kokoro/Qwen | 既有发布和语音实现 | 保留按需准备、独立 worker；不隐式云回退 |

| 数据与私人通道保留原位置 | 当前用户明确要求，代码仍有依赖 | Dots、模型、Qwen 旧环境和用户数据不因目录整理搬迁 |
| 同一 Git 仓库持续开发 | 原根目录与 origin 已核对 | 新文档/工具纳入原公共范围；保留历史与发布链 |
| 台账为进度唯一维护来源 | 多时期计划并存导致进度误判 | JSON 生成进度和归并页；CI 检查漂移、缺失项和依赖 |

## 2026-10-27：两态连续母片与独立播放（当前路线）

用户将范围缩为工作与看向用户，授权仅生成一条15秒720p连续母片。已从该母片裁出四段并免费本地超分4K，主应用按工作循环、转向用户、用户循环、返回工作调度；状态停留使用循环视频，不再停成静帧。对话框立即响应，人物在片段安全边界跟随，快速改选取最新目标。失败保图、明确重试、静态回切、男女声线及原对话/语音/遥控流程保留。

当前工程与本地候选的证据见[接入记录](two-state-app-integration-2026-10-27.md)、[候选验收](release-0.6.0-readiness.md)。不依赖Wallpaper Engine或生成服务运行；不能称逐像素无缝、原生4K或完成真实设备验收。2026-10-28全面审查在该范围上修复可靠性和依赖问题，没有追加生成或公开发布。此前三态、静态与Live2D研究均作为历史保留。

## 2026-10-24：先做三状态转场，只准备素材（历史阶段）

用户将这一阶段明确收敛为工作、望窗、看向用户，并告知稍后提供视频工具，先准备素材。当前交付为[三状态素材制作单](three-state-video-kit-2026-10-24.md)：复用旧版三张写实候选原图，配六条有向转场提示词及首尾映射；停留暂用静帧。捧杯、托腮、拿杯闭环及五姿态微动循环不进入本阶段。

旧图与五姿态方案保留。本次没有调用视频生成、购买订阅、替换主应用或制作新的图片；实际原图为1586×992。先验证工作与用户间的两个方向，之后补齐其余四段。素材包不是已完成视频或已实现播放调度，最终接缝仍需检查实际成片；原功能回归与FIX-17在后续集成时继续承担验收要求。

## 2026-10-23：保留五姿态，重新开放连续动作路线（本阶段范围由上文收敛）

用户在两次指出沙发漂移后，确认仍保留工作、捧杯、托腮、看雨、看向用户五种姿态，并允许重新考虑视频，以画面一致性和自然衔接为目标。此前“仅静态”的研究限制被这一最新要求取代；运行中的主应用仍使用现有静态素材，没有自动恢复旧视频入口。

[新制作方案](five-pose-continuity-plan-2026-10-23.md)建议简化家具构图，保留全部动作，以固定场景及短动作片段配合静帧停留；先检验拿杯/放杯闭环，再决定是否扩展。生成视频和自动抠像均不保证几何一致；三维同资产离线渲染作为需要更强控制时的后备路线。模型和工具事实见[来源核查](character-continuity-sources-2026-10-23.md)。此处只有用户的五姿态目标与开放路线已确认，具体混合制作方案尚处设计/小样验证阶段。

## 2026-10-22：人物壁纸方向调整（历史决策，研究范围由上文更新）

用户明确放弃本轮讨论的视频片段路线，回到静态人物壁纸，优先扩充女生姿态并增加轻微雨声和键盘声。首轮小样后进一步取消过渡图，采用直接切换，并否定厚重的合成音。2026-10-23 最终选择工作、捧杯、托腮、看雨、陪伴五种可长期停留的完整姿态，删除读书；详见[第二版五姿态](still-set-v2-implementation.md)。沿用先前本地超分方案输出3840×2400，明确区别于原生4K绘画。

视频制作、H3/Wan 选型和视频超分停止后续推进，精细 Live2D 也不进入本轮实现。已有研究和试用证据保留；原本已验证的调查不改写成未发生，未完成的动态交付后置并注明已被当前路线取代。用户随后授权推进，ART-09 第一阶段已退出主应用视频入口、兼容旧设置并恢复原画启动，交付[独立小样](static-wallpaper-preview.md)；尚未替换运行中的旧试用包或发布新安装包。同期完成的遥控焦点、失败重试和声线一致性修复已保留。

## 待决事项

**DEC-01：新增后端账户和计费边界。** 2026-10-22 发布检查依据[Anthropic 官方 SDK 说明](https://code.claude.com/docs/en/agent-sdk/overview)，确认未经批准的第三方产品不可提供订阅登录/额度。本项目没有此类批准；0.5.0 将 Claude 标为实验，并要求用户自行配置 API Key 或官方云平台 API 认证，由 CLI 的实际认证类型把关，拒绝纯 OAuth/未知认证，费用提示明确。Codex 登录方式不变，不自动创建或替换任何凭据。这是分发边界修正，不代表用户已同意切换计费；新增后端逐家真实认证及扩大正式支持仍待验收。

**DEC-02：原 TUI 共存和多个后台任务。** 现行产品已采用壁纸气泡与工作台；原 TUI 同任务双客户端控制、最多三个活动任务及同目录并发不是当前已经完成的能力。旧条目保留为待决/后置，不能直接删除，也不能把桌面界面当作该要求通过。决定是否继续投入时，要列出用户收益、协议可行性、隔离策略和验收成本。
