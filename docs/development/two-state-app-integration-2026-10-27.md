# 两态动态壁纸主应用接入

## 当前状态与范围

用户要求完成一条连续母片、四段剪辑、循环与切换、主应用接入及质量审核，最终达到可发布状态。本次已完成该范围的工程交付和本地候选安装包，交付包含实际主应用。素材方案见[连续母片制作单](two-state-continuous-master-2026-10-27.md)，最终证据和限制见[0.6.0候选验收](release-0.6.0-readiness.md)。

用户明确批准新增最多255积分、仅生成一条后，15秒720p连续母片已按重新核对的255积分报价单次生成、下载及验证。四段正式3840×2160视频、两张实际视频回退帧及哈希清单已接入主应用，原静态模式保留。720p与4K三个闭合接点、生产页面回归、真实桌面启动及0.6.0安装生命周期已完成，尚未公开发布。历史独立片段没有作为本次母片使用。

## 产品行为

- 女生新增动态开关，使用工作循环、工作到用户、用户循环、用户到工作四段。工作和陪伴均持续顺向播放视频；转身只播放一次。旧设置默认保持静态模式，男生保留静态方案。
- 自动模式下，呼出对话、听写、朗读或等待确认请求看向用户，结束后回到工作。固定工作/陪伴可试听，但听写和朗读优先。切换在已审核的片段边界发生；已开始的转身完成后再响应最新请求。
- 双视频解码器提前准备下一段，当前画面保持到新段可以显示。后台、手动暂停和锁屏沿用现有暂停通道；加载或解码失败保留画面，工作台明确显示重试入口。
- 声线仅通过原人物事务统一提交。静态/动态开关和姿态变化不重设自定义声线。环境音仍由一个实例持有；仅工作循环允许轻敲，转身和陪伴停键盘，听写静音，朗读降低雨声。
- 主应用只读取自身本地运行资源，使用有边界的字节范围流；不调用 Steam、Wallpaper Engine 或任何视频生成服务。

## 失败恢复

FIX-17 使用人物请求、已提交人物、画面版本和实际新画面回报约束恢复。旧画面的活动刷新不能清除后来发生的加载错误；实际显示有效姿态后可以恢复，无需多点一次人物重试。

静态序列记住失败的选择版本，普通状态刷新不再无限重载；用户重试或新选择创建新的版本。动态解码错误也停止自动尝试，显式重试重新准备媒体。

## 验证与放行

- `npm run test:motion`：离线验证四段时序、快速请求、暂停、错误保图、媒体范围、声线与草稿保持。
- `npm run qa:motion -- --run`：在忽略的测试目录生成小型运动测试图，运行生产页面、构建包和桥接接口，覆盖真实 Electron 解码、工作台、听写静音、朗读降音、人物切换和重试。实际回归通过；默认仅显示帮助。它不证明正式人物素材的美术质量或4K性能。
- `npm run qa:stills -- --pose-recovery`：此前失败的坏姿态到有效姿态场景已经通过；自定义声线保持，工作台恢复实际姿态并隐藏旧重试提示。
- 正式母片已核对两个循环自接、双向转场、回到工作接点及4K对照；代码复审、来源/许可记录、封装和限定安装回退验收已完成。下述早期阶段记录保留其当时的未完成项，当前放行范围以[候选验收](release-0.6.0-readiness.md)为准。

本阶段测试不访问真实 Agent 账户、麦克风或遥控器硬件；已有硬件与多 CLI 安装验收边界保持。

这一步的四项离线测试覆盖缺失/改动文件、别名/额外记录、私人材料排除和已有成品保护。早期素材未安装时，实际调用测试包入口已确认清晰失败，且没有创建不完整安装包目录；现正式素材完整时构建和校验通过。文件校验只证明字节完整，不能代替真实视频解码、美术、4K播放或安装验收。素材清单格式见[构建说明](../build.md)。

## 正式媒体与桌面结果

母片361帧统一超分，输出时间戳逐帧与原片一致；四段交付再规范为24fps。查看同帧脸部对照、循环端点及生产截图，人物比例和场景布局保持，超分使纹理更清楚同时皮肤更平滑。三处4K闭合接点的整体平均差异为1.72、1.53、1.73，未触发旧整体突跳诊断；雨滴和细小表情不是逐像素相同。
