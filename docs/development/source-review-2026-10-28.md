## Standards：两项确认的 P2

### STD-01 / TOOL-05：Claude 探针认证规则与应用相反

位置：`tools/probes/cli-agents/claude-probe.mjs:88`，首次请求在约第 94 行；应用规则为 `prototypes/live2d-codex/backend/claude-agent.mjs:20–28`，目标约束见 [product.md](product.md)。

维护探针要求 `loggedIn && authMethod === 'claude.ai' && apiProvider === 'firstParty'`，读到 SDK accountInfo 后只记录，不应用产品认证规则便发测试请求。主应用允许支持的云 API 或明确 API key 来源，拒绝纯订阅；产品也明确 Claude 实验入口不能使用订阅额度。

离线直接执行原始 guard 并调用应用实际认证函数，得到：API key 探针拒绝/应用接受；cloud 探针拒绝/应用接受；subscription-only 探针接受/应用拒绝。没有调用真实账号或推理。影响是 AGT-03 的正式维护入口可能误拒绝支持环境，也可能给产品不允许的认证产生误导性验收证据。

建议复用认证策略，在第一条请求前验证解析后的账号来源，补三类离线契约并同步探针说明。当前 help 测试只证明无副作用，不能证明 live 策略正确。

### STD-02 / TOOL-06：人物切换 GUI 用例拦截旧模型资源

位置：`tools/qa/gui/cases/character-switch.mjs:59–64`，首次失败等待约第 93–94 行；当前资源请求见 `prototypes/live2d-codex/renderer/still-wallpaper.js:20–22`。

隔离 VM 执行当前 still renderer 全部控制流和原始拦截函数：实际新资源命中 0、held 回调 0，人物已正常 ready；旧模型 URL 正控制命中 1、held 1。由此可确认当前故障注入失效，完整旧用例会等不到预期加载/挂起状态。没有把这份离线复现冒充原生 GUI 执行结果。
