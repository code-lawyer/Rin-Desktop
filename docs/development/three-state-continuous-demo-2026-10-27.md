日期：2026-10-27。关联ART-09，承接[六向转场制作](three-state-transition-production-2026-10-27.md)。

用户反馈视频间首尾画面似乎不吻合，要求把实际片段串起来展示工作、望窗、看向用户的完整效果。本轮仅使用已经完成的成片，在本地制作连续样片；没有新增生成、上传或积分消费，没有替换主应用。

## 时间线

采用已有的工作→望窗、望窗→用户、用户→工作三条超分4K视频，每条实际4.016667秒。首个工作状态及每段末尾停留各4秒，合计28.05秒。停留直接复制对应视频的实际首帧或末帧，不换用独立姿态图。

| 时间 | 画面 |
| --- | --- |
| 0–4秒 | 工作停留 |
| 4–8.016667秒 | 工作转向窗外 |
| 8.016667–12.016667秒 | 望窗停留 |
| 12.016667–16.033333秒 | 望窗转向用户 |
| 16.033333–20.033333秒 | 看向用户停留 |
| 20.033333–24.05秒 | 用户转回工作 |
| 24.05–28.05秒 | 工作停留 |

12.016667秒和20.033333秒是两处实际跨片切换。样片采用直接切换，没有叠化、形变对齐或重新生成过渡帧，保留现有素材的真实接缝。4秒停留是演示节奏；正式应用的停留时间仍需由用户操作和状态调度控制。

输入来自已有本地三状态4K素材包，输出位于新的 `work/qa/transition-demo` 子目录，不覆盖原素材或已有输出。默认只显示帮助，不读取素材、启动FFmpeg或连接账户。

交付包含3840×2160完整版（约44.80MB）、1920×1080快速预览（约12.85MB）、完整时间线联系表，以及两处切换前后相邻帧对照。两版均静音，保留原视频AI标记。

成片采用60Hz恒定时间线，复制原帧和停留帧，保持动作时长；这不是生成新动作或光流补帧。两版均为1683帧、28.05秒。首次本地草稿因帧率转换使每段多保留一帧重复尾帧，实际28.10秒，未交付；增加明确片段长度裁剪后，最终输出与预定时间线一致。

- 已查看完整联系表和两处实际输出的相邻帧，顺序为工作、望窗、用户、工作，停留取自当前片段。

## 用户建议裁剪后的诊断与对照

同日用户提出先剪辑已有视频，不重新生成。本轮检查上述三条720p原片及4K成品的全部97帧，并分别比较末尾1.5秒与开头0.5秒的候选配对。还检查了每段内部的相邻帧变化，避免只比较两个切口而忽略进入/离开停留时的闪动。

检查发现两个不同的问题：

- 单看跨片末帧与首帧，现有端点仍是扫描范围内最接近的一对；向内裁剪没有让这一对像素更一致。
- 每条原片的第0→1帧（约0.05秒），以及第92→93/94帧（约3.88–3.92秒）有明显纹理和局部形状变化。720p已经存在，4K保留了变化；不能把原因全部归于超分。其表现与片段端点向参考图靠拢、内部画面重新解释细节相符，但没有证据确认生成服务内部的具体实现。

因此裁剪版去掉这批不稳定头尾，再在保留完整转头动作的范围内选择接缝。查看三组完整画面对照及头尾12帧联系表后，选择下列范围；时间为原片位置，右端不包含。

| --- | --- | --- |
| 工作→望窗 | 0.416667–3.633333秒，第10–86帧 | 3.216667秒 |
| 望窗→用户 | 0.383333–3.583333秒，第9–85帧 | 3.20秒 |
| 用户→工作 | 0.50–3.883333秒，第12–92帧 | 3.383333秒 |

以320×180采样的头部/手部/全画面加权差值辅助比较，三个循环边界前后各0.5秒内的最大单帧变化约下降37%、41%、53%。这衡量的是去掉头尾突变后的变化峰值，不是视觉质量提升百分比，也不代表跨片切口本身更一致：裁剪后的单个切口差值反而高于原末帧/首帧。人物、头发和家具的局部差异仍存在，需用户观看连续播放决定是否采用。

## 动态待机需求澄清

用户随后明确指出，工作等状态应持续播放循环视频，静帧停留使整体呈现“动作—冻结—动作”的卡顿感。此前六条生成的范围仅为工作↔望窗、工作↔用户、望窗↔用户，每条约4秒；没有任何同状态循环片段。4K超分、完整拼接和裁剪版均为这些素材的派生文件，不计作新增生成。现有播放器在转场结束后暂停于末帧，两个连续样片都使用各4秒静帧停留，因此当前实现确实缺少动态待机。实际解码性能还需另测，不能将所有卡顿归为此原因。

最新体验目标要求至少三条状态循环和既有六条转场，共九类素材。历史“本批次不含循环”仅描述此前已执行的生成范围，不再代表目标体验：

| 状态循环 | 持续活动 | 待验收内容 |
| --- | --- | --- |
| 工作 | 轻敲键盘与自然停顿，轻微呼吸、偶尔眨眼 | 手指和电脑稳定；循环不重置姿态、不反复转头 |
| 望窗 | 持续看窗外，轻微呼吸、眨眼及细小视线变化 | 头部总体朝向不变；人物和家具不漂移 |
| 看向用户 | 保持面向用户，轻微呼吸和眨眼 | 保持回应姿态；不自行生成持续说话口型 |

先制作并验收一条工作循环，再验证“工作循环→既有工作到用户转场”的实际衔接，之后扩展另两条循环。每条循环都需检查自身首尾、循环到转场、转场到循环；目前六条转场的同状态端点仍有细节差异，因此“补三条循环”是素材结构下限，不保证自动获得无缝结果。待机期间继续播放当前循环，预备下一片段及可用衔接点，界面和语音操作不得等待整条循环播完。

本轮仅核对库存和记录需求，没有生成循环、修改播放器或接入主应用。既有短暂保持姿态的片段尚未通过自然循环验收；不能把冻结末帧、反复转头或简单倒放当作已完成动态待机。新增付费生成需先取得实际报价和新的明确授权，先前六条的额度不自动延续。
