# 已下载动态壁纸的接入调研

2026-10-22，ART-03。范围是识别本机正在使用的 Wallpaper Engine 壁纸、检查可用文件和动态机制、确定主应用接入边界。本轮没有替换桌面壁纸、修改第三方文件或实现正式兼容模式；ART-02 的 Live2D 美术验收失败仍然保留。

## 已确认的事实

- 从 Steam 库位置、Wallpaper Engine 进程路径及配置中的当前显示器选择定位到同一个 Web 壁纸项目。当前项目的确认依据是配置与运行进程，不是对实时桌面画面的截图；官方 `getWallpaper` 命令在本次调用中没有返回文本。
- 下载目录可读取 `project.json`、HTML、CSS、JavaScript、封面与 WebM 视频。它提供发布后的网页源码和媒体，不包含可编辑 Live2D 模型、人物分层原稿或视频生成工程。
- 当前项目有 31 段不同的视频，每段提供原画质、1440p、1080p 三档，共 93 个 WebM 文件。三套人物穿搭有专门的动态陪伴循环区间；其他穿搭主要提供入场、定格或整段重播。
- 实际探测到 1080p 样例为 VP9 视频、60 fps、Opus 音频，时长约 23.19 秒。动作来自视频帧，页面代码没有实时人体网格或 Live2D 参数控制。
- 作者在项目说明中称，多数视频由 Seedance 2.5 生成，再经 Topaz 放大和插帧。这个制作工具链属于作者自述，未在本项目中复现；输出分辨率不等于原生生成细节。

已在只绑定回环地址的临时服务中打开原网页，实际播放一套 1440p 动态陪伴素材。视频 DOM 显示 2560×1440、可播放数据就绪，备用视频预定位在 8 秒循环起点。后续观察到“循环衔接暂时中断，点播放继续”提示：独立浏览器的播放、寻址、帧回调及后台行为仍需适配，不能据此宣称完整循环兼容或 Wallpaper Engine 自身存在同样故障。临时服务未修改原应用设置，预览与本机调查输出仅保留在忽略的 `work/qa` 中。

## 可以借鉴的实现

| 机制 | 源码中的做法 | 对本项目的价值 |
| --- | --- | --- |
| 入场与待机分离 | 为每段素材记录循环开始帧、结束帧和帧率；先播放入场，再重复指定区间 | 避免人物不断重复入场动作，适合桌面长期陪伴 |
| 两个视频元素交接 | 当前视频播放时，备用视频提前加载并寻址；收到实际视频帧回调后换层 | 比播完后临时加载下一段更适合连续播放，仍需在目标宿主验证 |
| 换装过渡 | 使用背景静帧、预加载和短淡入淡出遮蔽解码等待 | 保持完整人物比例，不需要把原画拆成形变网格 |
| 明确播放状态 | 区分加载、播放、暂停、切换、定格、编辑和失败，并取消过期操作 | 可复用设计思路，避免快速切换时旧任务覆盖新选择 |
| 质量和暂停 | 多档素材；处理宿主暂停、页面可见性和暂停后的衔接 | 为实机资源占用与全屏应用共存提供控制点 |

这些是设计参考，不是把第三方实现和素材复制到公开发布包的授权。

## 推荐接入顺序

**第一阶段：Wallpaper Engine 渲染，Rin Desktop 提供对话与语音。**

让 Wallpaper Engine 继续管理桌面背景、视频和场景特效。本应用提供独立气泡、听写、Agent、朗读和工作台。需要时通过官方命令切换、暂停、恢复壁纸或调整壁纸已暴露的属性。这条路线既覆盖视频/Web 壁纸，也覆盖不能直接交给 Electron 播放的 Scene 壁纸。

主应用 `main.cjs` 已有 `--visual=hidden` 分支，可跳过角色窗口展示及 WallpaperHost 挂载，对话与工作台为独立窗口；根启动器也会转发此参数。但它目前用于验证，仍创建和加载原角色窗口，启动检查仍要求原模型资源，人物设置仍走原来的确认流程。因此只能作为改造基础，尚不是已交付的外部壁纸模式。

正式实施时应做到：外部模式不创建原角色渲染器，不抢占桌面背景宿主；对话气泡可独立定位；明确每套壁纸与声线的映射；加载/切换失败保留原有效组合并提供重试。需要实际验证快捷键、桌面点击、层级、全屏暂停、重启恢复和资源占用。

**第二阶段：本地视频素材导入。**

如果希望不依赖 Wallpaper Engine，先支持用户选择本地 MP4/WebM，保存素材路径和明确的循环区间。播放器借鉴预加载和状态机，缺失文件时保留旧画面并提供重试。素材作为用户本地资源引用，不随公开安装包分发。接入完整第三方网页比视频导入复杂，需要独立、无 Node 和应用特权桥的沙箱宿主，并适配 Wallpaper Engine 属性/暂停接口。

**Live2D 仍是另一项能力。**

视频能够表现连续转头、眨眼、呼吸和发丝运动，但动作已经录制好。它不能响应任意角度的鼠标跟随，也不能仅凭音量或音素让已有画面准确说出任意 TTS 文本。现阶段可实现“动态人物陪伴 + 正常语音播报”；任意内容的准确口型需要专门模型或额外视频生成/口型处理链，不能标注为已完成实时 Live2D。

## 文件类型与验证边界

| 下载类型 | 常见交付 | 接入判断 |
| --- | --- | --- |
| Video | 视频文件 | 可先做本地视频播放器，循环质量取决于片段和衔接 |
| Web | HTML、JS、CSS 与媒体 | 可检查源码；直接嵌入仍需处理接口、解码和隔离 |
| Scene | `scene.pkg` 等打包资源 | 由 Wallpaper Engine 渲染最稳妥；不是通用视频或 Live2D 文件，下载包不等于完整编辑工程 |

本轮验证了资源可读、项目类型、媒体编码、网页可播放和主应用接入入口。没有验证完整桌面共存、长期循环、实时语音口型、新人物美术、性能、安装或分发。公共文档不保存设备配置、下载列表或机器绝对路径。

参考：[Wallpaper Engine 官方文件类型与编辑说明](https://help.wallpaperengine.io/en/functionality/editingwallpapers.html)、[官方命令行控制接口](https://help.wallpaperengine.io/en/functionality/cli.html)。
