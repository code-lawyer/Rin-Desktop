## 本地处理与结果

查看全片动作联系表、手部局部和循环/转场接缝，未在这些抽帧中发现严重脸手形变。原片第0到1帧及约5.88秒附近有较明显变化；保留第1至131帧，即0.05至5.50秒，得到5.45秒的顺向循环候选。未倒放、混合双脸或补绘人物。抽帧检查不能代替连续播放的动作与闪烁验收。

新片与旧片不只是时间错位。用雨窗固定区域检查缩放与位移后，在本次对照样片中对旧的工作→用户、用户→工作两条转场采用统一中心裁剪：720p分析范围1258×708，对应4K范围3774×2124，再缩回3840×2160并统一方形像素。新循环及全部原始素材保持原样；裁剪只应用于新导出的样片。该处理使两处新旧切口的加权像素差由约12降至约7，但仍高于原有三态素材间约2–3的差异，数值不能直接解释为视觉改善百分比。局部纹理重绘不能由全局缩放彻底修复。

使用已有Real-ESRGAN x4plus与FFmpeg免费超分到3840×2160，未下载新工具或模型。原片的145帧、6.016667秒及全部时间戳保持一致，原片、4K和左右对比完整解码通过。查看同帧脸部对比后，发丝和眼睛更清晰，皮肤也更平滑；4K尺寸不代表原生4K或接缝已修复。

连续预览的剪辑为三遍工作循环→看向用户→返回工作→三遍工作循环，39.55秒；看向用户暂不作停留，避免把尚未制作的用户循环伪装成动态完成。另输出工作循环连续十遍的54.50秒样片。容器以60Hz记录原有帧停留时间，未插值产生新的运动帧，也不插入数秒冻结停留。最终时序、全片解码及接缝输出记录在各样片报告中。

4K和1080p往返样片均2373帧、39.55秒，单循环327帧、5.45秒，十遍循环3270帧、54.50秒；四份输出均完整解码，所有帧时间戳符合60Hz网格。已查看整段联系表、循环自身接头和16.35秒、19.983333秒、23.20秒的实际跨片切口；构图较接近，但脸部、窗景和纹理仍有差异。11项转场离线回归通过，覆盖新增工具默认帮助无副作用及既有播放器失败保图/重试等契约，不代表新循环已集成播放器或主应用。

## 交付检查

1. 验720p原片的手指、脸型、电脑和家具，检查每帧及片头/片尾内部突变。
2. 同时选择循环自身、循环→工作到用户、用户到工作→循环的接点；检查动作方向和接缝前后速度，不能只比较两张静帧。
3. 制作工作循环反复播放及“工作循环→看向用户→返回工作→继续循环”的连续样片，停留期间不插入冻结帧。暂不把用户状态未生成循环的事实隐藏为完成。
4. 沿用既有Real-ESRGAN x4plus与FFmpeg超分流程，保留原片、帧时间戳和统一处理参数；本次虽有接缝差异，仍输出4K供对比，不据此放行美术。对比720p与4K的循环接缝、纹理闪烁和完整时序。
5. 用户接受持续动态和衔接后，再扩展望窗、用户循环与正式调度。主应用对话框、工作台、语音和遥控器需独立集成回归；界面和语音响应不得等待一个循环播完。

## 23.20秒整幅跳动反馈与原因

用户在连续播放中指出约23秒整幅画面跳动。逐帧复现确认：成品第1391到1392帧，即23.183333到23.200000秒，由用户→工作原片第88帧（3.666667秒）切换到新工作循环第1帧（0.05秒）。时间间隔为正常的1/60秒，源帧来源与既有剪辑记录一致；问题已经存在于解码后的成品内容中。截成两秒独立视频后仍稳定复现，不需要完整应用或播放器调度才能触发。

同一对源帧、相同320×180分析尺寸下，整帧RGB平均绝对差如下。该数字用于单变量定位，不是视觉质量评分，也不与上文头/手加权指标混用。

| 阶段 | 整帧差异 |
| --- | ---: |
| 原始720p，未裁剪 | 14.82 |
| 原始720p，沿用样片中心裁剪 | 8.64 |
| 4K超分，未裁剪 | 14.33 |
| 4K超分，沿用样片中心裁剪 | 8.34 |
| 最终1080p连续成品实际切口 | 8.38 |

窗景、窗框、灯和沙发四个固定区域同时出现突变；切口附近有实际运动的相邻帧整帧差异中位数约0.42。查看原始720p及最终成品前后帧，人物头部/坐姿、沙发反光与褶皱、窗外光点和植物纹理同时变化。主要原因是独立生成的旧返回片段与新工作循环未共享相同的实际场景和姿态，硬切将这些差异集中到一帧。4K处理不是主要来源，取消中心裁剪反而更差。参考图相同不代表生成后的首尾帧仍与旧素材相同。

进一步仅以雨窗估计缩放/平移，最优窗口配准约为额外放大0.25%、横移2个720p像素；窗景局部差异由10.26降至8.88，但全画面差异由9.93升至10.33。这是另一个640×360分析尺度的独立诊断，不与上表数值直接混用。结果表明现有残差不只是统一缩放/平移；单一全局调整无法同时解决背景与人物的局部变化。本轮未将这个候选处理应用到交付样片，也未伪称修复。

维护的[接缝复现工具](../../tools/qa/video-seam.mjs)输出原始哈希、实际源帧映射、分阶段对照和两秒复现。完整样片及最小片段均触发明确的整帧突变信号；11项离线回归只证明工具帮助无副作用与已有播放器契约，不能抵消这个仍为失败的视觉接点。当前结论是原因已定位、接点未修复，需先验证该局部修整，再扩充另外两种循环。未新增生成、上传、积分支出或主应用修改。

## 制作流程复盘与下一步建议（尚未执行）

进一步核对已保存的草稿验证，两个有序首尾引用确实指向同一张上传图片，不是引用顺序或素材接错。该图片取自工作→用户的0.333333秒，未成为所有工作入口共用的真实输出帧。将新循环第0、1、8、60、131、144帧与上传图按同一320×180尺寸比较，整帧差异约14.56–16.64；连第0帧也未原样复制参考图。提示词已明确固定镜头、家具、背景、首尾姿态和低速动作，但实际结果仍发生构图/细节变化。继续强化同类文字不能被视为可靠的工程约束。

流程上的问题是先独立完成六段转场，再补循环，最后试图用相近帧将不同的实际场景拼接。状态名相同不意味着其像素、坐姿和动作速度相同。应分别处理固定场景一致性、人物轮廓/姿态一致性和运动连续性，而不是用统一裁剪承担三者。

建议先验证现有素材的一个局部接点，不新增视频生成：

1. 只选约23秒附近2–3秒进行小样。以已有一帧为坐标及场景基准，逐段匹配构图和曝光，保留原片及当前失败对照。
2. 场景复用同一份像素：窗框、房间、沙发、桌子和灯保持一致；如果保留雨滴动态，让它成为跨状态连续播放的独立背景层，不能每换人物片段就重置。人物遮挡后新显露的区域需要一次性补全并验收，不能由每段视频各自定义家具。
3. 人物用随视频跟踪的精确选区，检查发丝、手臂孔洞、衣袖和坐垫接触处，并保留统一桌沿/扶手前景及遮挡关系。此前粗轮廓带入旧沙发的失败见[场景返修](still-scene-consistency-2026-10-23.md)，本次不能复用为最终蒙版。自动分割只能提供初稿。
4. 背景稳定后再挑人物姿态接近、动作速度低的交接点；有少量残差时试约0.2–0.4秒的局部过渡，检查脸、手及头发，不直接对整帧做长渐变。不强行拉伸脸型，也不把替换单个首尾帧当作修复，后者只可能把跳动推到下一帧。不能靠插帧使两套家具变成同一套。
5. 先看正常速度、慢放和反复循环，再查看4K原尺寸及完整家具轮廓。固定场景差异必须由独立确认的人物/遮挡范围解释；不能仅检查避开边缘的几个矩形。无整体跳、双影、穿帮和明显皮肤纹理闪变后，再扩为完整往返及其他状态。若人物接点仍需明显变形才能衔接，应停止该候选并保留失败证据。

可用的免费技术包括FFmpeg按蒙版逐像素合成，以及SAM 2的视频选区传播；后者不是已验证的透明发丝抠像成品，需环境准备、边界修整和本素材验收。参见[FFmpeg官方滤镜源码文档](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/doc/filters.texi)、[SAM 2官方视频接口](https://github.com/facebookresearch/sam2#video-prediction)。本轮只核查能力，未安装或下载模型。

若现有素材的人物几何无法合理修整，再考虑有范围的重新生成：先验收状态循环，选定实际输出中的入场/出场帧，再围绕它制作缺失的转场；尽量从同一连续镜头获取相邻动作，降低独立场景重绘次数。连续镜头只天然保留相邻时间点的衔接，循环首尾及任意跳转仍需另验，不能承诺一次生成解决全部接缝。
